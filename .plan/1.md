## Approach

Without `ref`/`sha` in the source, Claude Code installs `main` HEAD under the release number (AkaLab-Tech/atelier#548). This task is the stop-gap for that: one manifest edit and nothing else.

1. In `.claude-plugin/marketplace.json`, change only the `source` object of the `atelier` entry (`plugins[0]`). Today it is `{"source":"github","repo":"AkaLab-Tech/atelier"}`. After the change it is:

   ```json
   "source": {
     "source": "github",
     "repo": "AkaLab-Tech/atelier",
     "ref": "v0.53.0",
     "sha": "5932526dd2909639abb4a990e301377c79d28425"
   }
   ```

   Keep the file's 2-space indentation and key order. Do not touch `name`, `description`, `homepage`, `repository`, `category`, `tags`, the top-level `name`/`description`/`owner`, or any other plugin entry.
2. Validate locally (the repo has no `package.json`, test runner or `.github/workflows`, so there is no CI suite. These checks are the whole gate):
   - `jq . .claude-plugin/marketplace.json` exits 0.
   - The atelier source is exactly what was asked:
     `jq -c '.plugins[] | select(.name=="atelier") | .source' .claude-plugin/marketplace.json` →
     `{"source":"github","repo":"AkaLab-Tech/atelier","ref":"v0.53.0","sha":"5932526dd2909639abb4a990e301377c79d28425"}`.
   - Nothing else changed: with the atelier `.source` deleted, the document matches `origin/main`:
     `diff <(git show origin/main:.claude-plugin/marketplace.json | jq -S 'del(.plugins[]|select(.name=="atelier")|.source)') <(jq -S 'del(.plugins[]|select(.name=="atelier")|.source)' .claude-plugin/marketplace.json)` prints nothing.
     Also confirm `git diff origin/main -- .claude-plugin/marketplace.json` touches only lines inside the atelier `source` block, so the other entries stay byte-identical, not just semantically equal.
   - Optional re-check that the sha is still the peeled tag commit: `git ls-remote https://github.com/AkaLab-Tech/atelier refs/tags/v0.53.0^{}` → `5932526dd2909639abb4a990e301377c79d28425`.
3. Tracking (`files` backend): in the same PR, move the `#1` entry from `ROADMAP.md` → `HISTORY.md` per the pre-merge tracking rule.

## Risks / open questions

- **The pin is manual until AkaLab-Tech/atelier#548 ships.** Every atelier release after v0.53.0 leaves the marketplace on v0.53.0 until someone moves it, so installs lag behind releases instead of tracking `main` HEAD. Until `atelier-release pin-marketplace` exists, the release session has to re-pin by hand through the normal chain. This is the intended trade-off, but the product lead should know about it.
- **`ref` and `sha` must agree.** If the tag is ever moved or re-created, the two fields disagree and an install may fail or resolve the wrong commit. Re-running `git ls-remote` before merging guards against this.
- **Id `#1` collides with this repo's GitHub PR #1.** A bare `#1` in a PR title or body links to the old PR #1 on GitHub, not to this task. That is harmless, but the PR text should spell it out as "roadmap task #1" to avoid confusion.
- **Install behaviour can only be checked after merge.** The repo has no CI, so whether Claude Code actually honours `ref`/`sha` is only confirmed by the operator's post-merge `gitCommitSha` check.
- **Auto-merge.** The diff is about 2 lines in 1 file, far under the `prSize` budget, and it touches no guarded paths (`package.json`, lockfile, workflows, Docker). Nothing should force a human fallback.
